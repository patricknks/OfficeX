# Skill: New Project

Create a new project inside `03 Projects/` by interviewing the user, then scaffolding the complete project workspace: folder structure, instruction files, navigation map, full slash command set, memory system integration, hook scripts, and implementation brief placeholder.

The result is a project that supports the full **research → decision → build → checkpoint** lifecycle out of the box, with all infrastructure in place so the user can start working immediately and resume cold sessions without context loss.

---

## How It Works

1. Duplicate `03 Projects/(PROJECT TEMPLATE)/` into a new folder (this preserves `.obsidian` config and plugins).
2. Interview the user one question at a time (6 questions max).
3. Based on answers, scaffold the full project: folders, files, commands, memory, hooks.
4. If the user doesn't have an answer yet, use sensible defaults and leave TODOs in the CLAUDE.md for them to fill in later.

**Key principle:** every project gets the **full toolkit** by default. Skills that aren't relevant can be removed by the user later, but having them all available eliminates friction and makes the system feel consistent across projects.

---

## Path Convention

Throughout this skill, **all paths are relative to the vault root**, not to this skill file. Every file and folder created for the new project lives under:

```
03 Projects/[Project Name]/
```

The only exception is the **memory folder**, which lives at Claude's home path:

```
~/.claude/projects/<project-slug>/memory/
```

The numbered prefixes (e.g. `04`, `05`) are assigned in Step 3 and depend on how many process folders the user defines. Wherever a step says "use the number assigned in Step 3", substitute the actual number before creating the file.

## Wikilinks & Frontmatter Convention

All `.md` files generated by this skill follow a consistent convention so the project is readable in both Obsidian and VSCode.

### Frontmatter (YAML Properties)

Every generated `.md` file begins with a YAML frontmatter block. This renders as **Properties** in Obsidian and is safely ignored by VSCode. Claude Code reads past it without confusion.

```yaml
---
title: [File title]
type: [file type — see table below]
project: "[[Project Name]]"
created: [today's date as YYYY-MM-DD]
tags:
  - [relevant tags]
---
```

Standard `type` values:

| File | type value |
|---|---|
| CLAUDE.md | `instructions` |
| COMMANDS.md | `commands` |
| MAP.md | `map` |
| DECISIONS.md | `journal/decisions` |
| RESEARCH.md | `journal/research` |
| SESSIONS.md | `journal/sessions` |
| IMPLEMENTATION_BRIEF.md | `implementation-brief` |
| Memory status file | `project` (in `metadata.type`) |
| Any skill file | `skill` |

### Wikilinks

Use wikilinks for **cross-references between files within the vault**. This builds the Obsidian graph and makes relationships visible.

| Use case | Format | Example |
|---|---|---|
| Reference another project file | `[[Filename]]` | `[[DECISIONS]]` |
| Reference a specific section | `[[Filename#Section]]` | `[[RESEARCH#api-rate-limits]]` |
| Reference with display text | `[[Filename\|display text]]` | `[[MAP\|project map]]` |
| Knowledge reference (theory, paper, external material) | `[[Knowledge References/filename\|Title]]` | `[[Knowledge References/method-overview\|Method Overview]]` |
| Project reference (internal spec, schema, blueprint) | `[[Project References/filename\|Title]]` | `[[Project References/system-blueprint\|System Blueprint]]` |
| External URL | `[text](url)` | `[docs](https://...)` |
| Claude Code file paths | backtick path | `` `05 Journal/DECISIONS.md` `` |

**Rules:**
- Use `[[wikilinks]]` when a human reading in Obsidian would benefit from clicking through.
- Use backtick paths when giving Claude Code a file location to act on.
- Never use `![[embed]]` — not supported in VSCode.
- Wikilink names match the filename without extension: `DECISIONS.md` → `[[DECISIONS]]`.

### Where wikilinks appear

- **Frontmatter `related:` field** — list files this document depends on or links to.
- **Journal entries** — each entry cross-links to related entries in other journal files.
- **MAP.md** — the master index of all wikilinks in the project.
- **CLAUDE.md** — human-readable references; file paths are still used for Claude Code instructions.

## Project Lifecycle Phases

Every project that uses this scaffold moves through 5 lifecycle phases. Each phase has the slash commands best suited to it. New Claude sessions can use the phase model to pick the right tool without having to read every command file.

| Phase | Purpose | Primary skills |
|---|---|---|
| **1. Bootstrap** | Project created, structure laid out | `new-project` (this), `/setup-journal` |
| **2. Discovery** | Gather knowledge, review existing material, identify gaps | `/index-reference`, `/auto-research`, `/research` |
| **3. Decision** | Crystallize direction (technical, strategic, or methodological) | `/decision`, `/build-brief` |
| **4. Build** | Execute on the brief — code/write/design/build, run iterations, validate | `/start` (resume), `/research` (log significant outputs), manual work |
| **5. Checkpoint** | Capture progress, close session safely | `/journal` (lightweight) or `/commit-discussion` (heavy) |

The scaffold installs **all 9 commands** so the user can move between phases freely. The COMMANDS.md generated in Step 6 explains when to use which.

## Interview Questions (Ask One at a Time)

Ask these questions conversationally using AskUserQuestion. Each answer can shape the next question. If someone says "I'm not sure yet" or gives a partial answer, don't push — just work with what you have.

### 1. What's the project called?
Used for the folder name under `03 Projects/`.

### 2. What is this project?
One paragraph. What are we building / doing / creating? Who is it for?

### 3. What does "shipped" look like?
What's the goal? What does success look like for this project? This becomes the prime directive in the CLAUDE.md — the thing Claude nudges toward.

### 4. Who else is involved?
Key people and their roles. Could be "just me" — that's fine.

### 5. What's the process from start to finish?
Walk me through how something goes from idea to done in this project. This is the big one — it creates the numbered project folders (inputs → process → outputs).

**If they're not sure:** Create a simple default structure:
- `03 Projects/[Project Name]/00 Ideas/` (input)
- `03 Projects/[Project Name]/01 In Progress/` (process)
- `03 Projects/[Project Name]/02 Done/` (output)

Tell them they can restructure later as the process becomes clearer.

### 6. Any rules or conventions Claude should follow?
Things Claude should always or never do in this project. Specific formats, naming conventions, etc. Optional — skip if they don't have any yet.

**Note:** There is no longer a question asking whether to install the journal/research infrastructure. **Every project gets the full toolkit by default** — it's lighter to ignore an unused skill than to have to add one later.

#### 9a. log_change.py

Create `03 Projects/[Project Name]/[NN] System/hooks/log_change.py`:

```python
#!/usr/bin/env python3
"""
PostToolUse hook — logs every file write/edit by Claude to a monthly code-log file.
Receives a JSON payload via stdin from Claude Code.

Writes to: [project root]/[NN+4] Journal/code-log/YYYY-MM.md
This file is write-only and never auto-read by Claude.
Read it explicitly only when a full audit of code changes is needed.
"""
import sys
import json
from datetime import datetime
from pathlib import Path

JOURNAL_FOLDER = "[NN+4] Journal"  # e.g. "05 Journal"
PROJECT_ROOT   = Path(__file__).parent.parent.parent
CODE_LOG_DIR   = PROJECT_ROOT / JOURNAL_FOLDER / "code-log"

def main():
    try:
        payload = json.load(sys.stdin)
    except Exception:
        sys.exit(0)

    tool = payload.get("tool_name", "")
    if tool not in ("Write", "Edit", "MultiEdit", "Create"):
        sys.exit(0)

    tool_input = payload.get("tool_input", {})
    file_path  = tool_input.get("file_path") or tool_input.get("path", "unknown file")
    now        = datetime.now()
    month_key  = now.strftime("%Y-%m")
    timestamp  = now.strftime("%Y-%m-%d %H:%M")

    entry = (
        f"\n## {timestamp} — {tool}: {file_path}\n\n"
        f"**Tool:** `{tool}`  \n"
        f"**File:** `{file_path}`\n\n"
        f"---\n"
    )

    try:
        CODE_LOG_DIR.mkdir(parents=True, exist_ok=True)
        month_file = CODE_LOG_DIR / f"{month_key}.md"
        if not month_file.exists():
            month_file.write_text(
                f"# Code Log — {month_key}\n\n"
                f"Auto-generated. Read only when explicitly requested.\n\n---\n",
                encoding="utf-8"
            )
        with open(month_file, "a", encoding="utf-8") as f:
            f.write(entry)
    except Exception as e:
        print(f"[log_change] Warning: {e}", file=sys.stderr)

if __name__ == "__main__":
    main()
```

#### 9b. log_session.py

Create `03 Projects/[Project Name]/[NN] System/hooks/log_session.py`:

```python
#!/usr/bin/env python3
"""
Stop hook — writes a session heartbeat to SESSIONS.md each time Claude finishes
a response turn, then trims the file to keep only the last MAX_SESSIONS entries.

Writes to: [project root]/[NN+4] Journal/SESSIONS.md
Claude auto-reads this file every session — the rolling window keeps it small.
"""
import sys
import json
from datetime import datetime
from pathlib import Path

JOURNAL_FOLDER = "[NN+4] Journal"  # e.g. "05 Journal"
PROJECT_ROOT   = Path(__file__).parent.parent.parent
SESSIONS_PATH  = PROJECT_ROOT / JOURNAL_FOLDER / "SESSIONS.md"
MAX_SESSIONS   = 5

def parse_entries(text):
    """Split SESSIONS.md into header and a list of entry strings."""
    lines    = text.split("\n")
    header   = []
    entries  = []
    current  = []
    in_entries = False

    for line in lines:
        if line.startswith("## ") and not in_entries:
            in_entries = True
        if in_entries:
            if line.startswith("## ") and current:
                entries.append("\n".join(current))
                current = []
            current.append(line)
        else:
            header.append(line)

    if current:
        entries.append("\n".join(current))

    return "\n".join(header), entries

def main():
    try:
        payload = json.load(sys.stdin)
    except Exception:
        sys.exit(0)

    now        = datetime.now().strftime("%Y-%m-%d %H:%M")
    session_id = payload.get("session_id", "unknown")[:8]

    new_entry = (
        f"## {now} — heartbeat (session {session_id})\n\n"
        f"_Claude finished a response turn. "
        f"Run `/journal` or `/commit-discussion` to replace this with a full session summary._\n\n"
        f"---"
    )

    try:
        if SESSIONS_PATH.exists():
            raw = SESSIONS_PATH.read_text(encoding="utf-8")
        else:
            raw = (
                f"# Recent Sessions\n\n"
                f"Rolling log — last {MAX_SESSIONS} entries only.\n\n"
                f"---\n"
            )

        header, entries = parse_entries(raw)

        trimmed = entries[-(MAX_SESSIONS - 1):] if len(entries) >= MAX_SESSIONS else entries
        trimmed.append(new_entry)

        rebuilt = header.rstrip("\n") + "\n\n" + "\n\n".join(trimmed) + "\n"
        SESSIONS_PATH.write_text(rebuilt, encoding="utf-8")

    except Exception as e:
        print(f"[log_session] Warning: {e}", file=sys.stderr)

if __name__ == "__main__":
    main()
```

## Skill Maintenance Notes

This skill is itself general-purpose — designed to scaffold any project. When patterns from individual projects prove valuable across projects, lift them up to this skill.

**Triggers for updating this skill:**

- A slash command in any project proves consistently useful → add to Step 7 template.
- A folder convention becomes standard across projects → update Step 3.
- A memory pattern emerges → update Step 8.
- A new hook proves valuable → update Step 9.

**Don't:**

- Hard-code project-specific domain knowledge here (trading, wavelets, ML — those belong in individual project CLAUDE.md files).
- Add tier-based complexity unless one tier is clearly insufficient — current single-tier approach keeps interview friction low.
- Add commands that have only been used in one project once — wait for a pattern.
